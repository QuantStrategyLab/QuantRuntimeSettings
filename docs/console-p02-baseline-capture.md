# P02 Worker baseline capture

The manual workflow captures one protected baseline for the fixed Worker. It leaves the release HOLD in effect. The reference is the #1091 backend tree with the asset map from the reviewed #1097 source. The dry-run bundle must match the digest of the verified publication. The workflow stops if the active module or the three frontend declarations differ.

Before a run, an authorized operator must verify the exact object's absence, bucket owner, workload identity, and permission to create and get that object. Store the capability receipt only in the protected runtime-strategy-switch environment secret QRS_P02_STORAGE_CAPABILITY_RECEIPT. The qrs-p02-storage-capability-v1 receipt includes bucket, owner_project, object, wif_provider, service_account, control_sha, control_tree, issued_at, expires_at, policy_readback_reviewed, create_permitted, get_permitted, and target_absent. The last four fields must be true. Use UTC timestamps and a validity of at most 24 hours.

Use the full reviewed control commit from main history as control_sha. Resolve its Git tree with git rev-parse on that commit's tree, and compare it with the reviewed tree before setting control_tree. The main dispatch revision must contain the control commit and the same workflow file. The run checks out the reviewed control commit and validates the receipt before installing dependencies. The existing reader variable precedence determines the workload identity.

Use one dispatch for the batch. Check run history and record the attempt before sending it. The workflow checks object absence, reads the active deployment, module and configuration, and rechecks the active deployment with at most four Worker GETs. It creates the fixed object with ifGenerationMatch=0 and verifies that exact generation. The protected object stores the control commit and tree, capture time, active identity, module and configuration digests, and asset comparison. Provider values and object contents stay out of the workflow log.

If a dispatch, write or readback is unconfirmed, stop and inspect the existing run or exact result object through the authorized channel. A verified capture records a point in time. Before any later authorized upload, activation or rollback, verify the active version and configuration again.
