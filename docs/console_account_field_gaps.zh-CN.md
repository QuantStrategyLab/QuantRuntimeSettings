# 控制台账户字段缺口清单

更新：2026-10-11（Asia/Shanghai）。只读整理，不修改受保护配置、密钥或部署。

## 口径与依据

- 数量来自 2026-10-09 线上目检（交接审计）：10 个账户配置条目里，9 个“券商环境”待确认，7 个“原生账户类型”待确认，1 个“实际启用”待确认；估值覆盖 8/10，现金覆盖 7/9；10 个账户都没有合格期间收益。
- 下面每个账户缺什么，是按当前 main（`13d78ec`）的源码推出来的：哪个字段从哪里来、哪些平台有接收合同。具体是哪个账户缺哪一项，要登录控制台读回才能最终确认；本文不写账号、金额或任何私有标识。
- 公开仓库只写平台和配置键名。账户实际 key 以受保护账户目录为准。

## 字段来源总表

| 字段 | 页面显示 | 实际来源 | 谁来补 |
| --- | --- | --- | --- |
| 券商环境 `broker_environment` | 实盘 / 模拟 / 待确认 | 受保护账户目录（account options）里的可选字段，不从券商取 | **用户或受保护配置维护人**给出准确值；后台不能猜，也不从账户名、模式或余额推断 |
| 原生账户类型 | 现金 / 保证金等 | Schwab：account-facts 可选 `broker_account_type`；Binance：专用钱包来源；其他平台**没有接收合同** | 后台补各平台接收合同（平台仓 + QRS 接收端）；用户不需要逐个确认 |
| 实际启用 | 运行中 / 已停 / 待确认 | 账户目录的 `runtime_status_target_id` 映射到运行状态，并需要新鲜的部署/定时器观察 | 后台：补准确映射；映射存在后等下一次自然周期读回 |
| 资产 / 现金 | 金额（按币种） | 各平台向 `/api/account-facts/sync` 发布的 account-facts | 平台发布任务；凭据过期时由用户授权续期 |
| 期间收益 | 券商原生 TWR | 目前只有 IBKR Flex 的接收代码已上线 | IBKR：用户在 GitHub 填 `IBKR_FLEX_TOKEN`、`IBKR_FLEX_QUERY_ID` 后由后台跑发布；其他平台暂无来源 |
| 持仓 | 未显示 | 平台运行报告的 `broker_reported_positions`；当前发布到控制台时被剥掉（接收端是精确键合同） | 后台：控制台接收端 + 前端面板（草稿 PR）+ 平台发布端停止剥离；Cloud Run 发版后才有数据 |

## 需要用户做的（只有这几项）

1. **券商环境**：在受保护账户目录里，给每个账户填上准确的 `live` 或 `paper`。可以直接告诉后台每个账户是实盘还是模拟，再由有权限的人写入受保护配置。后台不会自己改。
2. **IBKR 期间收益**：在 InteractiveBrokersPlatform 仓库填 `IBKR_FLEX_TOKEN`、`IBKR_FLEX_QUERY_ID`，确认后开开关、跑一次发布。
3. **Firstrade**：决定是否授权续期会话。
4. **Binance**：恢复交易流程前由用户决定，看板这边不处理。

## 后台可以做的（不需要用户逐项确认）

- 给 LongBridge、IBKR、Firstrade 补原生类型的接收合同（每个平台一个小 PR，先接收端后发布端）。
- 核对每个账户 `runtime_status_target_id` 的映射，补齐缺的那 1 项。
- 持仓：控制台接收端 + 只读面板（草稿 PR），平台发布端停止剥离持仓，等 Cloud Run 发版。
- 资产历史图按实际首个样本截断，并提示“历史仅 N 天”。

## 不做的

- 不从账户名、模式、余额或名称猜环境或类型。
- 缺数据不填零，不为了页面变绿隐藏异常。
- 不把技术缺字段都变成用户待确认项。
